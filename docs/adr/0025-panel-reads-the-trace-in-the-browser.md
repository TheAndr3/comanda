# O painel fala com a API pelo navegador e lê o Rastro num módulo só, que nunca quebra

O painel é uma página do lado do cliente: o navegador chama a API do `comanda serve` direto, no endereço de `NEXT_PUBLIC_COMANDA_API_URL`, e segue o Rastro com `EventSource` no SSE do ADR-0021. O chat mostra as falas que o envio devolve, e tudo o mais (delegações, ferramentas, bloqueios de guardrail, tokens, custo, cota) vem só do SSE. O `EventSource` reconecta sozinho mandando `Last-Event-ID`, e o painel o fecha ao ler `session_ended`, para não reconectar a um atendimento encerrado. Passar pela camada de servidor do Next.js (route handlers como proxy) foi descartado: exigiria um servidor Node para o painel, duplicaria o caminho do SSE e não serviria ao replay, que é exportado como site estático (ADR-0002); a API já libera a origem do painel por CORS.

A leitura do Rastro fica em `web/src/lib/trace`, o mesmo módulo para o SSE ao vivo e para os arquivos JSONL do replay (ADR-0010, ADR-0012). Ela junta chamada e resultado de ferramenta pelo `call_id`, soma tokens e custo por modelo como o resumo da CLI (ADR-0014) e nunca lança erro: um evento com versão de esquema desconhecida vira um passo que diz isso e mostra a linha original, sem interpretar os dados; um tipo novo na versão 1 aparece como evento genérico, porque tipos novos só acrescentam (ADR-0024); uma linha ilegível vira um passo de erro; e um evento repetido, com `seq` já lido, é ignorado. Assim um backend mais novo que o painel degrada a exibição, mas não derruba a tela nem esconde o que aconteceu.
