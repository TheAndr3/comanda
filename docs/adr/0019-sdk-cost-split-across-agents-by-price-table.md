# Custo do SDK dividido entre os agentes pela tabela de preços

O ADR-0014 manda usar o custo que o SDK informar e conferi-lo contra a tabela pública. O SDK informa custo por modelo e por turno (`model_usage` no `ResultMessage`), mas o Rastro registra uso por agente, e dois agentes podem usar o mesmo modelo. Então, a cada turno, os tokens são somados por agente e modelo a partir das respostas do modelo (o `usage` de cada `AssistantMessage`, contado uma vez por `message_id`, atribuído pelo `parent_tool_use_id` ao especialista da delegação), e o custo do SDK de cada modelo é dividido entre os agentes na proporção do custo que a tabela dá a cada um. O evento `usage` grava os dois valores, `cost_usd` (o usado) e `price_table_cost_usd` (a conferência), e a CLI mostra os dois lado a lado. Quando o SDK não informa custo, ou informa zero, `cost_usd` é o da tabela.

Se o SDK contar um modelo que não apareceu em nenhuma resposta, os tokens dele vão para o especialista do turno, se houve um só, ou para a Recepção. Os campos novos do evento `usage` (tokens lidos e gravados no cache e `price_table_cost_usd`) só acrescentam chaves, então a versão do esquema do Rastro (ADR-0010) continua 1.

## Revisão após a revisão do PR #17

O `model_usage` do `ResultMessage` é o acumulado da conexão do cliente do SDK, que o runtime reaproveita entre os turnos. O runtime guarda o último valor por modelo e usa a diferença; se algum contador diminuir, a conexão recomeçou e o valor atual já é do turno. Sem isso, o custo de cada turno incluía os anteriores e o custo por atendimento crescia de forma quadrática.

O total de cada modelo no turno passou a ser o que o SDK contou. As respostas continuam dizendo quem usou o quê, mas não bastam sozinhas: a resposta final só de texto de um especialista e os `output_tokens` finais não chegam (por isso `forward_subagent_text=True`, para ao menos receber as mensagens dos especialistas). O que as respostas somam fica com cada agente e o que faltou até o total do SDK é repartido entre os agentes daquele modelo, na proporção do que cada um já tinha; o custo do SDK é dividido como antes. A chave de `model_usage` casa com o modelo de uma resposta se for igual, igual ao `canonicalModel`, ou se um id for prefixo do outro (id com data), para não contar o mesmo modelo duas vezes. O resultado que um especialista devolve à Recepção chega ao Rastro sem o rodapé de controle do CLI (`agentId` e `<usage>`), que não é fala do especialista e iria ao SSE e ao replay público.

Dois modelos são o mesmo só se os ids forem iguais (a chave de `model_usage` ou o `canonicalModel`) ou se um for o outro com a data no fim (`-YYYYMMDD`); `claude-sonnet-4` e `claude-sonnet-4-5-20250929` não se juntam. Se todos os pesos de um modelo forem zero, o custo do SDK é dividido por igual entre os agentes.
